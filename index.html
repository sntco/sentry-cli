SENTRY · DEVELOPER PREVIEW

Vault credentials.
Your command line.

The separate sentry CLI lets local commands use selected vault fields after approval in Sentry.

Development preview. Apple silicon and macOS 27 or later. Requires the matching Sentry development app; the production App Store connection is still being qualified. The CLI is ad-hoc signed and not notarized.

Install

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash

That installs the current preview, configures zsh/bash command discovery and enables automatic update checks at login and daily. No Swift, Xcode or administrator password is needed. If your current terminal cannot find sentry, open a new terminal once.

Then run sentry --help. Installation does not install or unlock the Sentry app.

Use a saved field

sentry run --env 'API_TOKEN=Hosting account/password' -- /absolute/path/to/command
sentry access list
sentry access revoke 'Hosting account'

Use the exact, unique saved item title, quoted in field references. Open and unlock Sentry, then run your command and choose Allow once, Allow always or Deny. Allow always covers the entire item for any local program while Sentry is unlocked. Commands can expose credentials they receive; check their behavior and output.

Automatic updates

The CLI checks for updates at login and daily while your Mac session is active. Verified updates switch atomically without stopping running commands. Offline or rejected downloads preserve the installed version and are retried on a later scheduled check. Keep the app on the matching current protocol.

Uninstall

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash -s -- --uninstall

Uninstall removes verified CLI versions, the scheduled updater and its managed PATH entries. It preserves the app, vault and unrelated shell settings. Changed or unknown files are preserved for inspection.

Advanced installation details

Inspect the installer or inspect versioned downloads. Only the current signed preview is installable. The command lives at ~/.local/bin/sentry. A child installer cannot modify the terminal that launched it; automatic shell setup takes effect in a new terminal. Custom zsh configuration selected through ZDOTDIR is recorded at installation. An interrupted install may require inspection of its lock or incomplete files before retrying.

What is verified?

Each release includes the executable, SHA-256 checksum and source/toolchain/protocol manifest. The installer checks the checksum, ad-hoc signature and architecture before installing. Updates also require release metadata signed by the publisher key pinned in the installer. The metadata binds the binary and installer hashes, revision and expiry, with downgrade and replay refusals. The first curl command trusts the HTTPS website to deliver that installer and its pinned key. This update signature is separate from Apple Developer ID signing.

If macOS blocks execution, stop and report the result. The installer does not remove quarantine or disable Gatekeeper. Developer ID signing and notarization are planned before production launch. Keep the app and CLI on the same current protocol; older prototype formats are refused.
