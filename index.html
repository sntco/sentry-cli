Your command line.

Use saved credentials in local commands, with approval in Sentry.

Apple silicon · macOS 27+ · matching Sentry development app required. Ad-hoc signed, not notarized; production App Store connection still being qualified.

Install

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash

Installs the CLI, sets up your shell and enables automatic updates at login and daily. Open a new terminal once if needed.

Use it

Open and unlock Sentry. Replace the example item titles with your own, then choose Allow once or Allow always when prompted.

Use a token

sentry run --env 'API_TOKEN=Hosting account/password' -- /path/to/tool

Run sudo with a saved password

sentry run --stdin 'Mac admin/password' -- \
  /usr/bin/sudo -S -k /usr/bin/id -u

Save your current macOS user's password in “Mac admin”. -S reads it from stdin; -k requests fresh authentication. This example prints 0 when authorized. Your user must have sudo permission.

Send a secure note to a script

sentry run --stdin 'Deployment notes/note' -- /path/to/script

The script reads the saved text from stdin, without an added newline.

Manage access

sentry access list
sentry access revoke 'Hosting account'

Allow always covers the whole item for any local program while Sentry is unlocked. The list shows remembered permissions; revoke makes the next request prompt again.

Uninstall

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash -s -- --uninstall
Installation and security details

The CLI is separate from the app. Installation needs no Swift, Xcode or administrator password. It configures zsh/bash command discovery at ~/.local/bin/sentry; a running terminal may need reopening. sentry --help lists the options.

References use exact, unique item titles and field paths. Commands receive the selected credential and can expose it through their output. Stdin is consumed by the receiving program; the sudo example is for a command that needs no additional stdin.

Updates require publisher-signed metadata, matching hashes, architecture and ad-hoc code signature checks. Verified versions switch atomically; failed or offline checks preserve the installed version. The first curl command trusts HTTPS for its installer and pinned publisher key. This is separate from Apple Developer ID signing.

Uninstall removes verified CLI versions, the updater and managed shell entries. It preserves the app, vault, unrelated settings and unknown or changed files. Interrupted setup may need inspection; power-loss durability is not qualified.

If macOS blocks execution, stop and report it. The installer does not remove quarantine or disable Gatekeeper. Developer ID/notarization, production App Store communication and clean-Mac qualification remain pending. Keep the app and CLI on the matching current protocol.
