AGENT AUTHENTICATION LAYER

Your agentic auth layer.

An agentic auth layer gives agents controlled access to your vault and browser. Approve what they can read, write or fill through the app, CLI app and Chrome extension.

1. Install

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash

Open a new terminal, then run sentry --help. The installer sets up the CLI, but does not install or unlock the app.

2. Search, read and write

Explore supported item types and fields with sentry schema. To find an item, search its non-secret metadata, then describe the selected result:

sentry schema
sentry item search --host-file /private/host-pin.json < /private/search.json
sentry item describe --host-file /private/host-pin.json < /private/selection.json

Each search or description requires approval in the unlocked app. Results contain metadata and field paths, not secret values. Selecting an item does not grant permission to read or change it.

Read an approved field into a command:

sentry run --env 'API_TOKEN=Hosting account/password' -- /absolute/path/to/command

Create a Login using a private JSON request file and an enrolled connection:

sentry login create --automation-file /private/connection.json < /private/request.json

The request contains a unique request ID, createLogin operation and Login fields. Newer builds also support login update; creation and updates require separate approvals. Commands receiving fields can expose them in their output.

3. Access restrictions

  • Device: keep an approval on this device or explicitly share it with trusted paired devices. You can exclude access locally on a device.
  • Time: allow once, choose a fixed duration, or allow indefinitely.
  • Fields: approve requested fields, or explicitly allow all fields in the item.
  • Operation: read, create and update have separate permissions. Remembered rules can be revoked.

4. Configure agent access

  1. Open the app and unlock your vault.
  2. Open the item you want to configure and choose Edit.
  3. Select Agent Allow to manage agent access for the item.
  4. Choose the allowed operation, fields, duration and device scope, including an indefinite rule when needed. Save the changes.

5. Browser use

  1. Pair the Chrome extension, enroll the agent and approve the Login's username and password fields.
  2. Use the CLI app to discover browser targets and select a target and Login.
  3. The app checks the target and saved origin, then sends the credentials through the bridge to the Chrome extension.
  4. The extension fills the form without submitting it. The password is not returned in the CLI response, though the website and its scripts receive the filled values.

6. Apple Watch approval

  1. On Mac, enable Use Apple Watch to authenticate in the app's Security settings.
  2. An eligible approval request automatically triggers one Watch authentication attempt.
  3. Success allows that request once; if it fails, approve manually in the app.
  4. Turn the setting off to stop Watch authentication for these requests and native unlock.

7. SSH keys, API credentials and certificates

The app stores SSH keys, API credentials and public certificates and releases approved fields. An agent can use external tools to prepare a temporary Keychain or SSH-agent and perform signing when it has the required private key and permissions. The app does not create those environments or sign; certificate items alone contain no private signing identity.

8. Automatic updates

The CLI checks for verified updates at login and daily. Failed or offline checks leave the installed version in place.

9. Uninstall

curl -fsSL https://sntco.github.io/sentry-cli/install.sh | bash -s -- --uninstall

Uninstall removes verified CLI versions, the scheduled updater and its managed PATH entries. It preserves the app, vault and unrelated shell settings. Changed or unknown files are preserved for inspection.

10. Background mode

Planned. Background mode will let the CLI and browser extension work without the main app open.

Development preview. Apple silicon and macOS 27 or later. Requires the matching development app; the production App Store connection is still being qualified. The CLI is ad-hoc signed and not notarized yet.
